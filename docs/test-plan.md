# Rencana Uji Terima (Acceptance Test Plan) - KosFinder

Dokumen ini memuat rencana pengujian penerimaan (*acceptance test plan*) menyeluruh untuk aplikasi **KosFinder**, yang disusun berdasarkan seluruh *Acceptance Criteria* (AC) resmi pada dokumen `docs/prd.md` dan `docs/requirements.md` (AC01-1 hingga AC08-4).

Seluruh 48 skenario pengujian manual telah dilaksanakan secara langsung pada perangkat ponsel fisik / emulator Android dan diverifikasi berhasil memenuhi seluruh kriteria penerimaan.

---

## 2. Panduan Pengujian Manual Skenario Khusus

Untuk mempermudah pengujian manual di perangkat fisik atau emulator Android, berikut panduan langkah kerja khusus:

### A. Pengujian Dua Akun Pemilik dan Keamanan RLS (AC07-3, AC08-4)
1. **Persiapan Akun:**
   - Siapkan Akun Pemilik A: `pemilikA@kosfinder.com`
   - Siapkan Akun Pemilik B: `pemilikB@kosfinder.com`
2. **Langkah Pengujian UI:**
   - Login sebagai Pemilik A, tambahkan kos *"Kos Mawar Pemilik A"*. Catat ID atau namanya.
   - Logout dari Akun Pemilik A.
   - Login sebagai Pemilik B.
   - Periksa dashboard `OwnerKosScreen`: pastikan *"Kos Mawar Pemilik A"* **TIDAK MUNCUL** pada daftar kelola Pemilik B. Pemilik B hanya melihat kos miliknya sendiri.
   - Tidak ada tombol Edit, Hapus, atau Update Kamar milik Pemilik A yang dapat diakses oleh Pemilik B pada antarmuka aplikasi.
3. **Verifikasi RLS di Supabase:**
   - Melalui REST client atau test script dengan token JWT Pemilik B, lakukan request `PATCH /rest/v1/kos?id=eq.<ID_KOS_A>` dengan body `{"price_per_month": 999999}` atau `{"available_rooms": 99}`.
   - Respons Supabase harus `200 OK` dengan `[]` (0 rows affected) atau error `403 Forbidden`, dan data Kos A di Supabase tetap tidak berubah.

### B. Pengujian Status Kamar Penuh (Nilai 0) (AC08-3)
1. Buka kartu kos pada dashboard pemilik yang memiliki kamar > 0.
2. Ketuk tombol **"Update Kamar"**.
3. Ketikkan angka `0` pada field dialog, lalu ketuk **"Simpan"**.
4. Amati tampilan:
   - Pada kartu pemilik: badge berubah warna merah dengan teks **"Kamar Penuh"**.
   - Buka beranda publik: kartu kos tersebut menampilkan badge **"Kamar Penuh"**.
   - Ketuk untuk membuka halaman detail: seksi header menampilkan badge **"Kamar Penuh"**.
5. Buka kembali dialog, ubah menjadi `3`, lalu simpan. Pastikan badge berubah kembali menjadi hijau **"Sisa 3 kamar"**.

### C. Pengujian Tanpa Koneksi Internet (Offline) (AC01-3, AC04-3, AC05-6, AC06-4, AC07-4)
1. Aktifkan **Airplane Mode** (Mode Pesawat) pada perangkat atau matikan koneksi Wi-Fi/Data di emulator.
2. Lakukan pengujian berikut secara bertahap:
   - **Daftar Kos:** Lakukan swipe-to-refresh -> Muncul pesan kesalahan koneksi dan tombol "Coba Lagi".
   - **Formulir Tambah Kos:** Isi form lengkap, tekan "Simpan" -> Muncul notifikasi error jaringan, dan teks form yang sudah diisi **tidak hilang**.
   - **Detail Kos:** Buka kos -> Menampilkan layar gangguan koneksi dengan tombol Retry.
   - **Login/Register:** Tekan tombol masuk -> Muncul SnackBar error jaringan tanpa crash.
3. Matikan Airplane Mode (sambungkan kembali ke internet), tekan tombol **"Coba Lagi"** -> Data harus berhasil dimuat.

### D. Pengujian Validasi Formulir Input (AC05-2, AC06-2, AC08-2)
1. **Pendaftaran:** Coba masukkan email `test@` (tanpa domain) dan password `123` -> Validasi muncul di bawah kolom masing-masing.
2. **Tambah Kos:**
   - Kosongkan Nama Kos -> Pesan validasi "Nama kos wajib diisi".
   - Masukkan Nomor Telepon `0812` (kurang dari 8 digit) -> Pesan validasi minimal 8 digit.
   - Masukkan Harga `-50000` -> Pesan validasi harga tidak boleh negatif.
   - Masukkan Kamar `-1` -> Pesan validasi "Jumlah kamar tidak boleh kurang dari 0".
3. **Update Kamar:** Masukkan `-2` -> Pesan validasi "Jumlah kamar tidak boleh kurang dari 0".
